# Как добавить сущность

**Сущностей в Emberfall пока нет.** Этот документ описывает, как их добавлять,
и — что важнее — чего при этом делать нельзя, потому что первая же ошибка здесь
стоит дорого.

## Главное правило

Клетки мира — **не** сущности. Их 14 миллионов, они обрабатываются
специализированным data-oriented циклом, и любая попытка представить их
единообразно с врагами и предметами разрушает и производительность, и
модель памяти. Клеточный мир остаётся тем, чем является.

Сущности — это то, чего мало: враги, NPC, снаряды, подбираемые предметы,
интерактивные объекты. Для них уместна отдельная небольшая архитектура.

## Рекомендуемая форма

Обычные структуры и системы, без generic ECS-фреймворка:

```c
#define MAX_PROJECTILES 256

typedef struct Projectile {
    Vector2 position;
    Vector2 velocity;
    float life;
    bool active;
} Projectile;

typedef struct ProjectileSystem {
    Projectile projectiles[MAX_PROJECTILES];
    int nextProjectile;
    Rng rng;
} ProjectileSystem;
```

Это ровно то, чем уже является `ParticleSystem`, и по тем же причинам:
фиксированная ёмкость, переиспользуемый пул, ноль аллокаций в кадре.

ECS вводится только тогда, когда появится конкретная проблема, которую он
решает, и она будет названа в ADR. «Так принято в больших движках» — не
причина.

## Куда что кладётся

| Что | Куда |
|---|---|
| Состояние и симуляция | новый модуль `src/<entity>.c/.h`, вызывается из `GameUpdate` |
| Владение | поле в `GameState`, инициализация в `GameReset`, seed через `RngStreamSeed` |
| Рисование | отдельный `src/<entity>_renderer.c`, вызывается из `RendererRenderScene` |
| Обратная связь | `GameEvent` — звук, тряска камеры, импульс игрока |
| Столкновения с миром | `WorldMaterialIsSolid` + субшаги, как в `PlayerResolveWorldCollision` |
| Настройки | именованные константы рядом с модулем, а не литералы по коду |

## Что обязательно продумать

1. **Порядок в кадре.** `GameUpdate` задаёт единственный порядок обновления.
   Сущность должна занять в нём явное место, а не «где-нибудь».
2. **Детерминизм.** Случайность — из собственного потока `Rng`, никогда из
   `GetRandomValue`. Иначе seed перестанет воспроизводить сессию.
3. **Никаких аллокаций в кадре.** Фиксированная ёмкость и честный счётчик
   отброшенных.
4. **Взаимодействие со всеми существующими силами.** Что делает с сущностью
   лазер, взрыв, силовой удар, криолуч, бур, лава, вода, падающий песок? На
   каждый ответ — headless-тест. Пары, о которых никто не подумал, — и есть
   место, где живут баги.
5. **Сон chunks.** Если сущность меняет мир, она обязана будить нужные chunks
   через обычные пути записи (`WorldSetCell` и родственные), а не писать в
   `cells` напрямую.

## Проверка

```sh
make test
make bench
make asan
```

Счётчики `cells/tick` и `chunks/tick` в benchmark не должны измениться в
сценариях, которых новая сущность не касается.
